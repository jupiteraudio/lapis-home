Field test: a desk or wireless system

About 20 minutes. It confirms that Lapis works with one real device and firmware, and records what does not. Check the hardware list first: a model and firmware nobody has confirmed yet helps the most.

Before you start

  • Never during a show or a live rehearsal. Use the shop, a warehouse or an empty venue.
  • Save a backup of the desk show (or the receiver setup) first. The write test changes channel names.
  • You need Lapis 2.32.1 or later, the Bridge, and your computer on the same network as the device (a cable straight to the desk or through a switch).
  • Write down: make and model, firmware version, how it is connected.

Steps for a desk

  1. Start the Bridge. Lapis opens in your browser, already paired; the Bridge button at the top right turns green.
  2. Find the desk. Network › Scan network, then Use as FOH desk on the desk that appears. If it does not appear, type the desk's address in the Console tab. Note whether the scan found it.
  3. Check the link. Console › Check bridge, and on X32, X Air and DiGiCo also Identify desk. Note what it says about model and firmware.
  4. Read test. Console › Read desk. Compare the names and colours (and 48V, where shown) with the desk screen, channel by channel. Note every difference.
  5. Write test. Change three channel names in Lapis (Inputs), then Console › Read desk, Push selected. Check the three names on the desk. Then Undo last push and check they are back.
  6. Follow test (desks that follow: X32, WING, Yamaha, dLive, Avantis, DiGiCo). Touch a channel on the desk and check Lapis follows within a few seconds.
  7. Drop test. Pull the network cable for 10 seconds and plug it back. Does Lapis reconnect by itself, or did you have to press Check bridge?
  8. Save the report. Show tab › Report a problem › Save report. The file holds the version, the Bridge state and its last messages. Leave "Include the open show" off unless it matters.

Gain, 48V, patch and snapshot changes are off in the Bridge panel until you switch them on. Leave them off for this test unless you want to try them; if you do, say so in the report.

Steps for wireless

  1. Start the Bridge, then Live › Wireless status: add the receiver or transmitter by its address.
  2. Read test. Compare name, frequency, battery and RF level (whatever the device shows) with its own screen.
  3. Live test. Switch a transmitter off and on, or change a name on the device. Does Lapis follow?
  4. Write test (Shure Axient Digital, ULX-D, SLX-D, QLX-D only). Switch on Allow receiver changes in the Bridge panel. RF › Receivers: link one channel, Push to receivers, check frequency and name on the receiver, then set them back.
  5. Drop test and report as for a desk (steps 7 and 8 above).

Sennheiser EW-DX or G4 on firmware 4.0 or later: if nothing answers, switch on legacy mode (SSCV1) in Sennheiser's WSM and try again. Tell us whether you needed it.

Send it back

Use the feedback form with type Field test result. Put the model and firmware under "Hardware used", each step as passed, failed or not possible under "What happened", and attach the report file and a photo of the device screen next to Lapis.

We may use your report to improve Lapis. Tell us in the form if you want your name on the hardware list.
